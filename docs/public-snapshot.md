# Public scientific source snapshot

This source snapshot starts from the reviewed EchoClass beta.24 implementation and prepares beta.25 for public inspection. It focuses on a reproducible scientific calculation, data/review provenance and the difference between an observed result and a model candidate.

## Included

The Node.js/TypeScript, SQLite and Python implementation, its regression tests, anonymous synthetic samples, method/follow-up studies and original code-generated figures are retained. The project, engineering, evidence-trail and scientific data workflows default to English and support Chinese switching. The older classroom workflow remains a separate, partly Chinese compatibility surface.

The twenty-record scientific fixture and its invented review events are unchanged. No real extraction, antimicrobial or classroom outcome is reported. Production analytics, scientific dependency versions and released migrations are unchanged from the source baseline.

## Excluded

Legacy experimental photographs, an infrared spectrum image, lecture video/poster and the binary molecular model are omitted because their redistribution provenance was not established. Views use source-drawn illustrations and synthetic-resource links instead. The public artifact carries no original repository history, environment secret, classroom database, uploaded evidence, account dump, backup or application document.

The original private development and deployment record remains separate. Its historical key-revocation task has not been independently confirmed; this export does not assert that it was completed. There is no provider credential in the source snapshot, and the scientific examples and reading pages require no provider key. Publishing source does not authorize using a historical key or deploying against historical classroom data.

## Check the source

```sh
npm run publication:check
npm run lint
npm run typecheck
npm test
npm run test:python
npm run test:integration
npm run project:trace -- --text
```

The publication checker reads tracked files, rejects runtime/binary/legacy-material files and credential-shaped content, and checks synthetic labels. It prints paths and reasons rather than any matched secret. It writes no runtime data. The compatibility `prepare-release` command now runs this read-only check instead of deleting databases or replacing environment files.

The checks are developer verification, not independent human statistical or security acceptance. The known-hypothesis simulation assumes specified curves and noise; the project does not establish high-performance-computing proficiency, parallel speedup, a chemically validated optimum or large-scale throughput.
