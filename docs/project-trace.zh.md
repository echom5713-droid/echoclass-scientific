# 追踪一份结果

[English](project-trace.en.md) · [可复现案例](reproducible-case.md)

公开页面 `/walkthrough` 沿着一条虚构记录，展示审核、封存输入和实际计算结果。默认英文，可切换中文。原生展开控件不依赖 JavaScript；页面不读取账号、课堂记录或模型回复。

## 运行证据追踪

按 [README](../README.md) 准备 Node.js 24 与固定的 Python 3.12.13 环境，从仓库根目录执行：

```sh
npm run project:trace -- --text
npm run project:trace -- --text --lang zh
npm run project:trace -- --json
```

命令检查全部二十份规范输入及其保存摘要，再检查有序数据集清单、绑定的审核身份和执行指纹。随后调用现有离线演示，验证实际 Python 结果，并确认它属于同一个数据集。JSON 保留原始标识、精确摘要、计算配置和实测运行身份，文本输出用于阅读。

记录 `synthetic-005` 包含 100 g 果皮、8.8 g 精油和 1% 氯化铵，对应的 8.8% 得率是一条观测。1% 组的五条观测均值为 9%，与 3% 组并列；二次模型提出未测的 2% 附近候选。并列结果和候选点都不是现实化学发现。

审核事件与审核者全部是虚构的。`provenance_kind: human` 只是测试事件类别，不能证明独立真人审核。测试输入的执行身份也为合成身份。命令另外报告实测的计算进程身份；离线讲解不构成生产报告的精确复现声明。

## 改动分离的副本

命令在内存中复制输入包，将选中记录的精油质量及对应得率从 8.8 改为 9.8，保留原摘要。输入字节校验拒绝这个副本，然后重新检查未改变的原件。它不会写入测试文件、课堂存储、记录、审核或报告。

练习验证的是摘要不匹配，不是数据库更正操作，也不能检验有权同时替换全部摘要的写入者，更不能证明测量真实。数据库快照隔离、权限和重启复算另有 [HTTP / 数据库 / 计算进程测试](../tests/integration/scientific-workflows.test.ts)。
